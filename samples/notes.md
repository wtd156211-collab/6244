# 现场记录

随手记的，回头看能少走点弯路。

- 出过一件事：模板里把用户昵称直接塞进 `<script>` 里的一段字符串，少转义了一个引号。有人把昵称改成
  `"; fetch("//x/y");//`，页面上的脚本就按改过的样子跑起来了。安全给的是高危，整改通知只写了「输出转义不
  完整」六个字。
- 当时想用统一替换的老办法收场：把 `<`、`>`、`&` 全换成实体，看着像修好了。这一手在属性里不生效——属性值里的
  引号没人管，填个 `" onmouseover="…` 就直接闭合了属性又接上个新属性，页面照样能被改。链接那块更离谱，
  `javascript:` 这类地址不带尖括号，替换表里根本没有它。
- 还有一次很隐蔽：地址里夹的是 `java` + 制表符 + `script:…`，前端拿原串做前缀匹配没认出来，浏览器认出来了。
  后来才定下：先去掉控制字符和空白，再判协议。
- 模板是业务同学自己写的，写法五花八门，最后只留了一小撮语法，够用就行；没列进说明的写法一律当场报错，别默默
  忽略，不然下一次还是同一个坑。
- 渲染结果要能逐字节比对；页面那边也要把每段属于哪种上下文、用的哪种转义摊开给人看，不然出了事谁也说不清是
  哪一段漏了。
- 现场是客户的机器，装不了东西：没有外网，pip 也拉不动，只能用 Python 自带的标准库。页面也是浏览器原生那一
  套，双击就能开。
- 交付前对方强调过：同一份素材跑两遍，结果必须逐字相同。
